# Web 布局重设计

继续使用 Flutter，同仓库共用业务逻辑，为 Web 单独安排页面结构。静态部署方式、数据模型、认证、路线计算与保存规则不变。此轮不新建第二套前端。

## 页面结构

| 页面 | 桌面布局 |
|---|---|
| 欢迎 | 左侧本地山水插画与品牌，右侧介绍、注册和登录入口 |
| 登录、注册、密码恢复 | 左侧品牌插画，右侧受控宽度的表单；窄屏回到单栏 |
| 主工作区 | 232px 网页侧栏，文字与图标横排、矩形选中态；取消 NavigationRail |
| 规划行程 | 留在主工作区；左侧行程信息与摘要，右侧人物选择，随后切换为地点操作区与地图 |
| 日期 | 普通状态只显示日期字段，点击打开 320px 弹层；不会随页面宽度放大 |
| 添加地点 | 桌面使用居中弹窗，保留搜索、主题筛选及原有选择规则；手机使用底部面板 |
| 首页 | 网页标题、刷新与创建行程操作；沿用已有行程内容和管理能力 |
| 个人中心 | 横向账号信息，成就与偏好双栏；保留原有占位统计和本地偏好能力 |
| 详情与设置 | 在同一侧栏工作区打开，阅读和表单区域仍限制宽度 |

`/routes/new` 保留为可刷新恢复的 URL，但不再离开主工作区打开一个没有导航的独立全屏向导。Android 继续使用原有分步流程、原生日期界面和底部导航。

表单使用更紧凑的间距、边框和按钮；沿用现有字体、暖褐色品牌色、浅中性色背景。插画由 Flutter 本地绘制，无额外网络图片或生成图片依赖。认证表单切换单双栏时保留输入；侧栏切换经过现有草稿退出确认。

## 检查

静态检查、全套 Flutter 测试、Web 浏览器测试及 Android/Web Release 构建的结果见 [验收记录](web_validation.md)。新增浏览器测试覆盖双栏认证切换保留邮箱、欢迎入口、规划嵌入工作区、日期弹层尺寸与选择结果。实际浏览器检查还覆盖网页侧栏可操作、人物选择、同一工作区进入地图规划、地点弹窗和离开草稿时确认。

真实地图、邮件认证、跨账号权限和完整设备矩阵仍按原记录待验收。样式调整不代替这些服务验收。
