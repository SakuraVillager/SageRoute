# 东坡景点资料与地图实施计划

**目标：** 按用户提供的 `notepad.html` 保存 37 条考订记录，支持三类等级、五大专题和完整详情。

**方式：** 在 Supabase 增加独立的 `dongpo_sites` 内容表，避免覆盖已有其他人物景点。导览使用已有 LocationRecord 映射扩展后的记录；路线规划和成就保持当前范围。原文逐条保留，专题作为编辑标签单独保存；定位依据和精度与历史证据等级分开。

## 顺序与验收

- [x] 1. 提取 37 条结构化数据；校验序号、必需字段、30/2/5 等级统计；补充可核查地图位置，待考点不伪造坐标。保存原文快照、JSON 和可重复导入工具。建立只读公共内容表，管理端导入后回读核对。
- [x] 2. 扩展 LocationRecord 和导览数据仓储；实现全部/确证/疑似/已佚筛选、绿黄红标记及文字提示。未知等级保留未评级，不能默认为确证。
- [x] 3. 增加五大专题标签，可与等级和搜索词组合；地图和列表使用同一筛选结果，无坐标景点仍可打开详情。
- [x] 4. 完整详情展示古今地名、时期、事件、相关诗文、出处、考订说明、等级及定位依据。照片记录包含 URL、摄影者、来源和授权信息；没有照片时明确显示缺失状态。
- [x] 5. 验证数据导入、模型往返、组合筛选、空结果和窄屏详情，运行 flutter pub get、flutter analyze、flutter test；渲染代表页面并保存截图。

## 输入限制

原始 HTML 无经纬度和现场照片，部分条目明确位置待考。照片须由团队提供，不能将生成图片或任意网络风景替代现场照片。原文存在需要复核的地望表述，保持源文并单独记录定位依据。Supabase 管理连接已恢复，37 条记录已写入并回读核验。30 条具参考位置，7 条待考；照片按用户要求后续补充。详见 docs/data/dongpo_catalog_delivery.md。
