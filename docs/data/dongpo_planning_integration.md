# 东坡杭州行迹接入路线规划

规划流程的「添加地点」内接入东坡杭州行迹主题路线，收录原始 37 条资料。若云端已有「苏轼·杭州行迹」等同义路线，则复用其名称和 ID；没有时提供「东坡杭州行迹」。首页独立推广入口已移除；原 `/dongpo` 资料地址保留兼容。原文、文献出处、考订说明、坐标说明与已授权照片沿用原始素材。

## 数据与身份

`PlanningCatalogRepository` 合并现有 `Location` / `Topic` 与 `dongpo_sites`，37 条资料共享原有规划 UI。优先使用 `catalog_key`（`dongpo-hangzhou-01` 至 `37`）关联已导入资料，其次匹配古今地名，最后使用 `assets/data/dongpo_planning_metadata.json` 中明确的旧地点完整名称；该文件也为原素材未填写分类的地点提供分类。对应到已有地点时保留 Location ID、原有分类、游览时长及原主题关联；同地点的其他历史记录同步增加主题和等级。新增资料使用独立的负数 ID，不与 Location 主键混用。

原始资料中 30 条具有参考坐标，7 条位置待考。全部资料均可筛选、查看详情。「允许选择参考位置」开关默认关闭；开启后，用户可手动选择有有效坐标但云端标记 `route_eligible = false` 的地点，卡片显示「参考位置」。关闭开关取消此类地点的勾选；缺少坐标的条目始终不可新增到路线。该开关只控制本次手动选点，不修改云端等级、规划资格或自动生成路线的规则。已有保存路线的途经点保持兼容。参考点的范围与依据保留在详情中。

遗存等级使用现有 `heritage_grade` 内容字段，并传递到规划模型的 `heritageGrade`。确证 `#237A4B`、疑似 `#B88309`、已佚 `#BA4242`；未评级为原地图棕色 `#96615A`。分类与等级使用相同的小标签组件，地图保留分类图案。草稿保存等级与完整资料；云端路线使用现有途经点名称、坐标和有效 Location 外键保存，重开时从本地素材恢复对应等级与资料，不依赖新增途经点字段。

主题标签包括水利治绩、交游酬唱、诗词题咏、民生善政。自然山水复用已有「自然景观」；若数据中已有明确同义标签，则优先保留已有名称。主题路线筛选与内容标签筛选相互独立，原「苏轼·西湖治水与六井」「苏轼·望湖楼与凤凰山」继续保留。

## 可选数据库同步

应用侧整合不要求先执行数据库变更。`supabase/setup_dongpo_planning.sql` 可将新主题和对应旧地点的等级、标签同步到云端。生成命令为 `python tools/prepare_dongpo_planning.py`，覆盖 31 个明确的旧地点名称对应。脚本可重复执行，添加可空的等级列与多值标签列，不更改原始史料、旧主题关联、坐标或用户路线；不创建迁移历史记录。

本次数据库管理接口返回无权限，因此该 SQL **尚未执行**。通过普通公开读取已确认云端现在已有 37 条带 `catalog_key` 的资料和「苏轼·杭州行迹」主题；本次改动复用这些数据，不会重复生成地点或主题。应用侧的旧地点标签补充可直接生效；该 SQL 仅供需要将旧记录的标签补充持久化时使用。
